# The use-case ledger

This is the fourth of the [four ledgers](../../CONTRIBUTING.md#the-four-ledgers)
that judge smock's tests. Every documented feature has an automated test,
or a recorded manual check with its reason, and every message a user can
see is asserted at least once. Each row below is one feature or one
message. It cites where the feature or the message comes from: a section
of smock's documents, a spec or an issue. It names the tests and the
checks that cover it, the ticket that adds what is missing, or the manual
check and why it is manual. The [boundary ledger](boundaries.md) does the
same for limits.

[Keeping the ledgers current](../../CONTRIBUTING.md#keeping-the-ledgers-current)
in CONTRIBUTING says how each change keeps them up to date.
`scripts/check-ledgers.py` checks every row on every push: each test a
row names must still be there, under that name and in that file, and each
status must agree with what the row names. Its docstring states the
format of the tables.

A row names the tests that show its feature best, not every test that
touches it. A test that a row names is the only test of that row for the
[removal rule](../../CONTRIBUTING.md#removing-a-test): a removal batch that
takes it away names another test that checks the row, and updates the
row, or the test stays.

## Baseline

A survey of the documents at d953f320 gave the first counts. Each row was
then checked again on the tip of the test review's integration branch,
be2b8e0b, against the code and the tests there.

| | At d953f320, as the survey counted | At be2b8e0b |
|---|---|---|
| Features | 99: 93 covered, 2 partly, 4 not | 99: 92 tested, 2 partly, 2 manual, 3 open |
| Messages asserted by no test | 22, 20 of which a user can see | none of the 22: 20 asserted, 2 deleted |
| The top-level help | never asserted | still open (#370) |

Since be2b8e0b, #370's test asserts the top-level help, with the
description it fixed: F12 is tested, and M23 asserted.

The survey's rows give 92 features covered, not the 93 of its summary: six
rows have no test (F12, F15, F39, F63, F98 and F99), and one is partly
tested (F96).

Of the survey's 22 messages, a corrected count at d953f320 is: 2 that no
input reaches (M07 and M08, since deleted), 3 that only a package's
interface shows (M14, M19 and M22), and 17 that a user can see. The
survey counted 20 a user can see.

## Changes since the survey

Rows whose status changed between d953f320 and be2b8e0b, and why:

- **F63**, the compatible endpoints: no test at d953f320. The SDK check
  now reads both through the official SDK (#349).
- **F95**, the Helm chart's values: the survey counted it covered, but
  its evidence says that two documented values, `definitions.gitSync.depth`
  and `definitions.gitSync.extraArgs`, are rendered by no test. Still true
  at be2b8e0b, so it was partly tested, with gap G1. Since then, #373's
  check renders both, so it is tested.
- **M01 to M06** (YAML), **M09 to M13** (templates), **M14** (XML),
  **M15 to M18** (the Admin API), **M19 and M20** (definitions), **M21 and
  M22** (`smock import-openapi`): asserted since, by #280, #281, #283 and
  #291.
- **M07 and M08**: no input reaches either, so each was deleted with the
  maintainer's approval (#280, #281), not asserted.
- **M14, M19 and M22**: only a package's interface shows them. The survey
  had the first two as invisible to users; #283 found the third: the CLI
  always gives the document before it converts.
- **M24**, the log line of the fallback when the operating system refuses
  a reset, was outside the survey's 22. It is a manual check: only an
  operating-system failure shows it.

## Gaps that no ticket closes

A gap that no ticket of the test review closes is filed as an issue, which
its row names.

- **G1, closed by #373.** The Helm chart's rendering tests checked no
  rendering of `definitions.gitSync.depth` or
  `definitions.gitSync.extraArgs`, which the chart's README documents
  (F95). The git-sync test now renders both, and checks that both git-sync
  containers carry them.
- **G2, #374.** The Helm chart's git-sync and OCI-image modes are rendered
  and admitted on kind, but never served. Serving them on kind is out of
  scope for now (#275, decision 5), so the issue is deferred, filed to be
  kept in sight (F96).
